# 五类道路检测数据集核查（2026-10-15）

目标类别：行人、自行车、电动自行车、汽车、公交车。此次补充资料核查只读取公开说明、类别定义、版本页，并查看1张公开电动车示例缩略图；没有下载完整数据、训练模型或取得新的精度结果。

## 选型结论

有相关公开检测数据，但尚未核实一套完整覆盖这五类、且明确区分电动自行车的现成路口数据。优先考虑 **Intersection-Flow-5K 作为路口基础**，MIO-TCD Localization作监控车辆/行人补充，BDD100K作通用道路补充；电动自行车需要另找可靠的道路专项标注或在目标路口补标。以下为候选与证据边界，不把项目页宣传等同于标注质量认证。

| 数据集 | 已核实规模/类别 | 场景、格式及入口 | 电动自行车状态 |
|---|---|---|---|
| Intersection-Flow-5K | 作者称6,928张1920×1080，7个城市路口；8类 | 固定路口，含昼夜和雨天；YOLO/VOC及测试集COCO；作者仓库指向Kaggle | 未确认独立类别；`engine`含义必须进一步核查 |
| MIO-TCD Localization | 官方137,743张；含pedestrian/bicycle/car/bus/motorcycle及多种货车 | 北美交通监控；官方提供矩形框及读写示例 | 不单列 |
| BDD100K Object Detection | 官方检测10类，含pedestrian/rider/car/truck/bus/train/motorcycle/bicycle/traffic light/traffic sign | 车载道路，Scalabel JSON；需按官方入口获取 | 不单列 |
| Roboflow e-bike-hbroc | 项目页2,194张；v2导出3,494张，单一`e-bike`类 | v2提供YOLOv5/8/11、COCO、VOC等导出入口；已看示例包含产品图 | 标签存在，但道路代表性与真实类别边界尚未审计 |

## 1. Intersection-Flow-5K：最贴近路口任务

来源：[作者仓库](https://github.com/AstronZh/Intersection-Flow-5K)、[作者提供的Kaggle入口](https://www.kaggle.com/datasets/starsw/intersection-flow-5k)、[FlowDet论文](https://arxiv.org/html/2508.19565v1)。

官方README给出训练5,483、验证722、测试723张，类别为vehicle、bus、bicycle、pedestrian、engine、truck、tricycle、obstacle。提供YOLO、VOC及测试集COCO格式的说明，适合本项目的轻量YOLO候选训练/评价。

需要核对的事项：

- 不能只凭`engine`这一名字就认定它代表电动自行车；论文表也只写Engine，未给出足以完成映射的定义。
- vehicle也应先检查具体边界，不能未经核查就等价为仅小汽车；bicycle类是否混入电动自行车同样待查。
- README只写“超过95,000框”，论文表1逐类数字合计406,758框。两者下界和详细程度不同，不能直接说逻辑矛盾，也不能当成已自行清点；实际版本与框数待下载核验。
- README提及README_zh.md，但当前main树核查只有README.md，未取得中文类别说明。
- 作者声明CC BY-NC-SA 4.0，许可用途限非商业。不要采用第三方重发页的MIT标识覆盖作者许可。

当前状态：作者说明和下载入口已核；完整压缩包下载、文件完整性、类别样本检查和独立路口划分审计均未执行。

## 2. MIO-TCD：选Localization子集

来源：[官方数据集页面](https://tcd.miovision.com/challenge/dataset.html)。

Localization有137,743张含目标框的监控图，标注包含行人、自行车、汽车、bus、摩托车及多种卡车，便于补充先前测试中出现的罐车/公交混淆。是否实际改进需要训练和独立评价，不能由类别存在就认定有效。

不要把648,959张Classification子集的目标裁剪图当成完整图像检测集。官方Localization页面提供框文件读写示例与整套下载入口，具体格式转换需在取得样本后核查。此数据未设独立电动自行车类；官方许可CC BY-NC-SA 4.0。北美路况与中国电动自行车密集路口存在场景差异。

## 3. BDD100K：道路泛化补充

来源：[作者仓库和官方获取导航](https://github.com/bdd100k/bdd100k)、[官方类别与标注格式](https://github.com/bdd100k/bdd100k/blob/master/doc/source/format.rst)。

官方检测评估包含10类，行人、自行车、汽车、bus、摩托车均在其中，但没有electric bicycle独立类。标签采用Scalabel JSON，不是下载后无需处理就能直接训练的YOLO TXT。该数据主要是车载视角，不是固定路口监控。

当前官方主页/文档域名的浏览读取出现错误，因此这里只给仍可读的作者GitHub导航，不声称整套下载链已测试成功。完整数据获取条件和许可应在实际下载前按其官方当前条款核对。

## 4. Roboflow e-bike：可用来筛选专项样本，不能当已合格的道路数据

来源：[项目页](https://universe.roboflow.com/project-vq6cj/e-bike-hbroc)、[v2版本和导出格式页](https://universe.roboflow.com/project-vq6cj/e-bike-hbroc/dataset/2)。

已核实单一标签`e-bike`。项目页显示2,194张图；v2显示3,494张（训练3,029、验证283、测试182），并声明训练样本增强输出3份、水平翻转、拉伸至640×640。**3,494不能当成3,494个独立原始场景**。其他版本数量亦不同，必须锁定版本。

v2页提供YOLOv5/8/11、COCO JSON、VOC XML等格式入口，页面许可CC BY 4.0。没有登录、调用收费推理或下载完整导出包；实际下载可能需要平台账号。

已实际查看项目公开示例缩略图，至少包含一张车辆产品展示图。不能据此判断全数据都是产品图，也不能将整个项目直接标为路口数据；需要抽查道路/电梯/产品图比例、电动与燃油摩托边界及矩形框质量。

项目还展示一个Roboflow 3.0 Fast在线模型，其页面给出mAP@50 49.7%、Precision85.0%、Recall27.0%。这只是项目页面报告，未复现，也不能等价为NX可离线部署权重；其召回指标不能支持“高准确率五类路口检测”。

## 其他来源及取舍

[VRUD](https://github.com/zzi4/VRUD)提供深圳城中村无人机混行数据资料，7类含自行车/摩托车及其他道路参与者。当前通过[官方表单](https://lab.autozyx.com/vrud.zh.html)申请，不能当作已取得完整RGB检测图像与标注。无人机视角、轨迹用途和未单列电动自行车，也使它不适合作为当前固定路口五类检测的首选。

此次没有把缺少真实下载文件的售卖/推广仓库列为已取得数据，也未将电梯专用电动车集当成道路泛化证据。

## 针对五类模型的处理原则

1. 先抽查类别和框的定义：骑行者与车是否合框、普通自行车与电动自行车是否分开、摩托车是否混标、bus是否包含长途客车。
2. 多来源图像不能只改类别编号就拼接。单类电动车图中的人、汽车等若没有标注，普通全监督检测训练会把这些未标目标当背景；须补齐标签、采用合适的部分标注训练方案，或筛选符合统一规则的数据。
3. 按路口/摄像头/视频序列划分训练、验证、测试；相邻帧及其增强副本必须留在同一侧。最终目标路口测试集应独立保留，评估每类Precision/Recall/AP。
4. 数据集存在不意味着已有合格权重，也不保证在NX达到30FPS。本轮未训练，未改变上一轮“电动自行车独立类和NX速度尚未验收”的结论。

仅此自有核查文档同步到研究仓库；完整第三方数据、标注、示例图和权重不随常规同步上传。
