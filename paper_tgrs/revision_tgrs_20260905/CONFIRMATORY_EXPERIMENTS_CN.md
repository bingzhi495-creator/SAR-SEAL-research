# TGRS 后续确认性实验执行方案

日期：2026-09-05。**这是执行方案，不是已完成实验或投稿合格声明。** 本轮仅核对现有文本、配置路径与文件目录；未加载 checkpoint、运行预测/评估、训练模型或修改原代码。以下产物名称是拟定名称，不代表文件已经生成。执行预算应在缓存盘点后估算，不预填 GPU 时长或预期正结果。

研究问题固定为：对同一已训练 SAR 实例分割载体，mask 空间关联、条件投票、局部边界修正和质量重排分别改变什么，是否在独立场景上有效，以及代价是多少。HRSID 现有载体使用辅助 MaskIoU 监督，PSeg-SSDD 现有载体使用标准 head；不能用跨数据集差值替代训练机制对照。

## 1. 最小执行顺序

| 优先级 | 必要工作 | 优先利用已有材料 | 何时需要新计算 |
|---|---|---|---|
| P0，先决条件 | 预测—配置—权重—评估器绑定；数据使用史 | 配置、日志、JSON、缓存、split lists | 绑定不全时补来源证据；仅最终预测不足以重建融合 |
| P1，先决条件 | 场景分组、独立开发/确认集合、预注册 | 原始场景元数据、已有标注 | 真正未用于开发的数据不足时，需要新场景；新划分通常要求重新训练载体 |
| P2 | 标准训练与辅助监督 × 固定后处理的匹配对照 | 旧结果只作诊断与预算依据 | 缺少同划分、同预算的训练分支时需新训练 |
| P3，核心算子 | 相同完整候选池上的融合对照和机制分桶 | 若缓存保留融合前候选，可直接重放 | 缺少候选/真实软概率时需固定权重重新前向；无需为每个融合规则重训 |
| P4，校正器 | 场景分组 OOF 残差；BPR × rerank；目标与匹配控制 | 旧 patch/feature/JSON 可检查格式与不变量 | OOF 残差通常需折内载体训练；确认性纠错器需重新拟合 |
| P5，与确认评估同步 | 预指定端点、配对区间、场景与训练变异 | 已有固定预测可复核“条件于已选模型”的区间 | 新确认预测完成后一次性执行锁定分析 |
| P6 | 1/4/8 views 的实测时延、显存和阶段开销 | 固定模型、固定图像集合、已存候选 | 必须实际运行推理计时；不能从文件时间戳推算 |

P0/P1 未通过，后续数字仍可作为探索或实现诊断，不能标作独立确认。优先完成 P2–P4 的关键对照，不先扩展更多 backbone、适配器或第九种融合变体。

## 2. P0：建立可复核证据链

**输入。** 已确认存在的材料包括 `runs/c0_maskiou_v2/{s0,s2,s3}/`、`runs/cp_pseg/{s0,s2,s3}/`、两套 `soup_s023/`、`runs/bpr/`、`runs/scic/`，以及 HRSID/PSeg-SSDD annotation JSON。仅文件存在不证明其中的预测对应论文表格。

**执行与输出。** 建立一行对应一个评估结果的 `artifact_lineage.csv`，至少记录：

- 数据集和 split JSON 的哈希；原始 scene ID、chip ID、裁块坐标及类别映射；是否曾参与训练、调参、选模或看结果。
- 代码 revision/改动摘要、完整 resolved config、checkpoint 哈希、初始化来源、训练 seed、head 类型、辅助损失权重 β、推理混合 λ、迭代数。Soup 另记录成员哈希、成员选择规则、平均键及缓冲区处理。
- 预测文件哈希、生成日志、模型来源、view IDs/尺度/翻转、坐标还原方式、分数语义、过滤阈值、融合前后数量、top-K 与 maxDets、评估器及依赖版本。
- BPR/rerank 各级稳定 instance ID、mask/RLE 和 score 的来源；几何特征来自哪个阶段；训练标签与最终评估标签的路径分离。

先在 CPU 侧检查缓存 schema、image ID 覆盖、重复/缺失记录、掩码尺寸、非有限数及各阶段字段不变量；再用记录中的评估设置复核旧结果。每个数据集选固定的少量、按场景分层的样本验证前向与缓存一致；这只是绑定检查，不能据此替代全量结果复核。像素与浮点输出的比较准则应分别声明。

**能支持的结论。** 某个报告端点确实来自指定模型与流程；不能据此证明泛化或查新。

**失败处理。** 无法绑定的行保留为未核实历史记录；先修复来源或重新生成。特别是只保存融合后 top-100、只保存图中 top-16 或只保存二值 mask 的缓存，分别不足以重放全候选融合或真实概率平均。

## 3. P1：真正独立的数据与预注册

设 **T** 为拟合场景，**D** 为开发场景，**H** 为最终确认场景。按原始 SAR 场景/获取批次分组；相邻、重叠裁块和同场景派生文件一起分配。记录港口、传感器、分辨率及时间信息；若部分元数据不可得，明确分组依据和不能排除的相关性。

已有 HRSID test 已用于规则选择，不能改名为 val 后恢复“未见测试”身份；已有 PSeg-SSDD test 的结果也已公开查看，不能继续调参后声称同一次独立迁移。优先使用此前未参与训练、模型选择或方法开发的新场景作为 H。若只能重分已有数据，必须从原始 COCO 初始化重新训练、排除 H 的全部后续训练来源，并披露历史使用；不能继续使用已训练过 H 的旧载体或纠错器。该方案提供更严格的场景外重评估，仍需审慎区分模型未见与研究过程完全未见。

在 D 上一次性确定所有规则，再锁定 H：模型与成员选择、随机种子、学习率/epoch、视图、候选过滤、融合参数、BPR 设置、rerank 目标与 α、比较对象、主端点、区间算法、失败/缺失处理和排除规则。保存带时间戳与哈希的 split manifest、配置清单和分析计划；H 的标签不进入选模、纠错监督、早停或人工挑例。确认结果无论正负均归档。

**输入/输出/边界。** 输入为场景来源与使用史；输出为锁定的 T/D/H 清单及预注册文档。只有足够独立的场景支持确认性泛化结论；场景过少时降低结论范围并报告精度不足，不能靠增加同场景 chip 数制造有效样本量。

## 4. P2：训练身份与后处理的匹配矩阵

在同一数据集、相同 T/D/H、COCO 初始化、R50 主干、数据增强、训练预算与配对随机种子下执行：

| 训练分支 | P=0：单视图原始输出 | P=1：锁定的完整后处理 |
|---|---|---|
| 标准 Mask2Former head，无辅助质量损失 | A0 | A1 |
| 辅助 MaskIoU 训练，β=0.5；最终 λ=0 | B0 | B1 |

每行两列必须使用同一个载体 checkpoint。P=1 的融合规则及超参数选择规则保持相同；BPR/rerank 使用该分支自己的 T 预测拟合，不能把辅助分支的纠错器直接套给标准分支作为唯一对照。该矩阵估计的是训练方案与完整处理流程的交互：报告 A1−A0、B1−B0 及两者之差。它不单独识别 gate 的收益，后者由 P3 隔离。

最小机制矩阵先使用单 checkpoint，避免将 soup 成员数引入训练效应。若最终主结果保留三成员 soup，另对两种训练分支按相同成员预算、开发集兼容性规则和已锁定组合进行对照，并如实计入额外训练。三个共享成员构成的一份 soup 不是三次独立重复。

建议至少三个预先指定的配对训练种子用于观察训练变异，逐种子给出完整四格；不从中选表现最好的一个。三个种子本身不能保证统计功效。若要把差异归因到**辅助损失本身**，还需同一辅助-head 实现下 β=0 与 β=0.5 的桥接对照，其他训练条件一致；stock head 与 aux head 的直接差异只能归于整套辅助训练方案。ImageNet 与 COCO 初始化的因果研究不属于这组最小实验，不能继续借用跨论文的 17.9 与 27.7 推导。

**输出。** 四格逐种子结果、配对差值与交互、完整训练身份表。

**失败降级。** 若处理只对某一种训练分支有效，结论限定到该分支；若无法补齐匹配训练，删除辅助监督/预训练的因果解释，仅保留现有各协议内的观察。

## 5. P3：同一候选池上拆开关联、门控和概率表示

一次固定前向，保存**全部融合前**候选：原坐标下 binary masks、真实 logits/probabilities、类别、原分数、view ID、稳定 candidate ID、坐标变换和过滤记录。所有算子重放同一份输入，输出用相同评价规则与 maxDets。各算子的专属参数在同一 D、同等预定搜索预算上选择；同时报告文献/实现默认设置及开发集选择结果。不要用一个失配的 Matrix-NMS 设置代表该算法。

| 对照 | 固定内容与要隔离的变化 |
|---|---|
| Box-NMS、mask-NMS/seed-only | 同分数和候选；分离 box/mask 相似度与代表选择。若 mask-NMS 与 seed-only 实现逐记录等价，报告等价，不制造两个独立证据 |
| Soft-NMS、Matrix-NMS | 记录 IoU 定义、kernel、σ、score decay、过滤时点和阈值；核查 decay 后排序与 top-K。默认与合理开发集配置均保留 |
| 无条件 binary vote、当前 cardinality gate | 同一 score-seeded mask-IoU 簇、同一 seed 分数；只切换是否依据候选数启用投票；明确 ≥半数与偶数平局规则 |
| Distinct-view gate | 先保持簇成员及投票权重不变，只把门控变量改为不同 view 数，隔离 gate 变量；另列“每视图只保留一个代表”的完整版本，不能把去重收益全部归给 gate |
| 经典 score-weighted mask voting | 实现并记录与 MNC/FCIS 相关的加权平均对照；相似度、成员、权重和二值化阈值分别标清 |
| 真实 probability mean 与 binary vote | 使用模型实际输出的非二值概率；记录 dtype、范围、分位数、0/1 以外的比例、对齐/插值、阈值及逐像素差异。不能把二值 mask 转 float 或插值后称为模型软概率 |

在不重训、不改候选的条件下，报告融合结果及 cluster-level 诊断：候选数与不同 view 数的联合分布、同 view 重复率、每簇 GT 匹配纯度、seed/vote 的 Δmask-IoU、被正确/错误合并的邻船、重复数和漏检。按预注册的目标尺度、近岸/远岸、局部实例密度分层；分桶边界只能由 T/D 确定。支持数不是方差估计；mask 变小也不等于质量下降。

**能支持的结论。** 分别识别 mask 关联与当前 gate 的增量，以及哪些簇收益或退化。

**失败降级。** Gate 未优于 seed-only 时，将其降为一种启发式选择，不称核心精度贡献；若 distinct-view 版更优，必须以新算法和新实验行报告，不能沿用旧 gate 数值。缓存缺少软概率时，该对照标为待补前向，不能推断“概率平均与投票等价”。

## 6. P4：OOF 残差、BPR 和重排的目标对照

**残差生成。** T 按场景分折，每折预测仅由未见该折场景的载体生成，构成 out-of-fold（OOF）训练残差；D 的预测由只在 T 拟合的载体生成，用于纠错器选模。同一图像的重叠 patch、同一实例候选不能跨纠错训练/验证分区。默认让纠错训练的上游预测步骤与部署前缀一致；原有单视图、in-sample 残差作为明确的训练来源对照。旧 NPZ 的随机 patch 划分不能仅改标签后声称 OOF。

OOF 解决的是拟合样本与残差来源的问题，不能保证与最终全 T 载体的错误分布相同；比较两者在 D 上的残差分布和校正表现。为控制预算，先用固定配对载体完成来源对照，再对保留方案进行预指定种子重复。

**四格接口。** 从同一份融合候选及稳定 instance ID 出发，输出：不加纠错、仅 BPR、仅 rerank、BPR+rerank。以保存的 ID 连接特征、粗掩码和精修掩码；若需复核旧的 IoU 重匹配路径，单列它与 ID 路径的对应率、未匹配及错误匹配，不把二者混成同一结果。

- BPR 比较 in-sample 与 OOF 训练、采用的无带 BPR 与受限形态学带版本。报告 mask AP、AP75、Boundary IoU/边界指标，以及带外像素是否逐位不变、ID/分数是否不变、拓扑破坏和漏修。新增边界指标前锁定实现与宽度定义，不能将欧氏带与当前重复 3×3 形态学操作混用。
- Rerank 对比当前 `max IoU to any GT` 目标与一个预先定义的重复感知目标。后者必须明确一对一分配、未分配/重复候选目标和 tie-breaking，避免多个同船重复候选都获得高质量标签。不要宣称它天然最优；保存两种监督与最终 COCO 贪心匹配之间的差异。
- 同时比较粗融合 mask 质量目标与 **BPR 后** mask 质量目标；特征在哪个阶段计算必须一致记录。以不改变 mask 的固定样本校验 MAE/校准与排序，最终仍通过 AP 判断任务效用，相关系数不能代替 AP。
- α 候选必须含 **0（空操作）**，并实际进入开发集选优，不能只显示为参考。当前 `scic_rerank.py` 会计算 α0 的 AP，但 `best_alpha` 仅在正 α 列表中更新；执行阶段应在隔离实现中修正并记录。α=0 必须保留原分数/掩码/实例记录；若开发集选择 0，就保留“不使用重排”的结果。

**输出。** 残差来源 manifest、按场景分组的 patch/feature 索引、四格结果、逐记录不变量与失败例、质量目标/匹配审计。

**失败降级。** OOF 后收益消失则不再把 in-sample 验证当作泛化依据；边界带只通过不变量检查而无精度增量时，将它作为实现约束；重排选择 α=0 或影响某类目标时，移出主配方或明确适用范围，不删除不利端点。

## 7. P5：端点、配对区间和结论规则

预注册时分别定义两个问题：**gate 相对 seed-only 的增量**，以及**完整配方相对原始载体的增量**。若主张面向近岸，建议以独立 H 的 inshore mask AP 为主端点，official/full mask AP、AP75 和远岸表现为预指定次端点；若实际部署侧重全场景，应在看 H 之前将 full AP 设为主端点。不要看到结果后交换主次。多个主比较采用预先约定的检验顺序或多重比较控制，完整报告所有比较。

以相同确认场景配对重采样两方法，并在每次重采样上重新聚合完整 COCO AP，不能平均逐图 AP。原始场景是独立单位，场景内 chips 一起进入；同一 scene 被重复抽中时正确处理重采样权重/重复 image ID。若按近岸/远岸分层，需要保持场景组而非拆散同源图像。混合场景先一起重采样再提取子集；official 包含两子集，三者不是三次独立验证。

同时报告：固定训练结果下的 paired scene-bootstrap 95% 区间、逐训练种子的配对差值与变异、每层有效场景/图像/目标数。训练重复与测试场景不确定性分别呈现；如采用层次 bootstrap，写清种子和 scene 两级如何抽样。重采样次数、随机种子及稳定性准则预注册，不能为使区间变正而追加重采样或挑种子。场景太少时明确区间不稳定；不得借外推强行作确定性结论。

若要声称“远岸不退化”，应在 D/应用需求阶段给出有意义的非劣界值及其理由，并按该界值检验；区间包含 0 不证明等效或安全。根据独立场景数量和应用可接受的最小效应规划精度，不根据旧测试中最有利的增量预设功效。所有失败、不收敛和缺失结果按锁定规则报告，不填预计正向数字。

## 8. P6：4 与 8 views 的真实计算代价

固定硬件、软件版本、精度、batch、数据加载方式和同一分层 chip 集合；明确模型冷启动是否计入。对 1/4/8 views 分别执行预先固定的 warm-up 与重复测量，GPU 阶段计时包含同步；另外测量包含图像预处理、CPU/GPU 传输、融合、BPR、rerank 和结果生成的端到端时间。随机化配置执行次序以减小缓存和温度顺序效应。

输出每配置 mean/median/P95 ms/chip、吞吐量、峰值 GPU 分配/保留显存、主机内存、每图候选数与 BPR patch 数，并按密度分层。报告 carrier 三成员训练、OOF 训练、纠错器拟合和开发搜索的开销；checkpoint 平均操作无需训练不等于 soup 无训练成本。不预填运行时间。

作为**解析输入工作量**而非时延预测，HRSID 名义正方形输入给出：

- 4 views `{800,960} × {identity,flip}`：`2×(800²+960²)/800² = 4.88` 倍单 800² 输入像素。
- 8 views `{640,800,960,1088} × {identity,flip}`：`2×(640²+800²+960²+1088²)/800² = 9.8592` 倍。

实际 resize/padding 后尺寸另外记录。此前审阅稿的 9.8432 是算术误差，应更正；平方和本身不包含 Gram 运算、纠错网络、并行度或传输，不能据此填“8×推理时延”。若四视图的独立性能与代价更合适，可按预注册的效用规则保留它，而非默认八视图必须成为主配置。

## 9. 可执行的前置检查建议

以下 PowerShell 仅用于后续授权执行时的定位与来源检查，不启动训练，也没有虚构执行脚本。所有路径已在本次目录或源码检查中出现。先确认环境可执行文件，再决定后续推理命令；不要假定某个环境能导入全部 detector 依赖，也不要用脚本 `--help` 代替无导入的源码审阅。
