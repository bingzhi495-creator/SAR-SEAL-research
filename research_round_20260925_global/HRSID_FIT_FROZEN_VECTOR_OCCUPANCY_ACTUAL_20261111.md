# HRSID 固定监督点的多边形覆盖率试验

在旧试点的三组基础上，新增一组直接计算官方多边形在每个输出像元中的面积比例。主要比较仍用相同点位的源栅格覆盖率。沿用原生 E24 冻结特征、匹配及 31 条共同小目标监督，四组各用 487 个相同点、相同初始化和 8 次 AdamW。只更新原查询投影的 65,792 个参数。新目标中 106 点不同于栅格占比，124 点为小数。两个原硬标签组和栅格占比组的更新、末端参数、归档及留出指标逐值复现。 [预锁方案](code/HRSID_FIT_FROZEN_VECTOR_OCCUPANCY_20261111/PROTOCOL.md) · [可复算入口](code/HRSID_FIT_FROZEN_VECTOR_OCCUPANCY_20261111/vector_occupancy_ablation.py)

| 留出裁剪组等权连续多边形 IoU | 值 |
| --- | ---: |
| 原冻结投影 | 81.5827% |
| 逐步中心硬标签 | 81.6228% |
| 单次复合中心硬标签 | 81.6878% |
| 源栅格覆盖率 | 81.6675% |
| 源多边形覆盖率 | 81.6399% |

多边形组相对栅格组为 **−0.0276 个百分点**，8 个裁剪留出组中 7 组持平、1 组下降。相对单次复合硬标签 −0.0479 点，直缩组和栅格覆盖率的连续 IoU 一致。预锁要求相对栅格覆盖率至少 +0.5 点且 8 组中至少 5 组为正。当前固定点与更新配方停止进入长训。 [实测汇总](results/HRSID_FIT_FROZEN_VECTOR_OCCUPANCY_ACTUAL_SAFE_20261111.json)

第一次尝试在 Torch 导入时因 DLL 初始化失败退出，未到达模型前向。用已验证的同版本独立 Python 入口和同一协议修正后，原工作进程退出 0，完成 24 次前向和四臂各 8 次更新。留出指从本次投影更新中留出，原冻结模型已训练过这些 FIT 图。本项结论限定于冻结头试点，无 DEV、TEST 或 AP 评分。
