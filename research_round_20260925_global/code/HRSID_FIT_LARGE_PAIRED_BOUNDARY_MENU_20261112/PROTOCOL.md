In the nearest two native-pixel chessboard contour depths, the add candidates are donor foreground outside anchor and the trim candidates are anchor foreground outside donor. Each receives the same edit count K = min(floor(anchor area / 20), number of available add sites, number of available trim sites). Sort by depth then row-major index. No donor or K=0 yields no edit. The depth-only comparator uses the same K and the exact selected depth histogram for each direction, with row-major ordering and no donor pixel membership. Keep the original query, box, score, rank, and the no-op option. There is no substitution of a donor mask.

For each menu report forced add/trim and a per-fold oracle choosing the greatest whole-mask IoU among add, trim and no-op. Strict ties prefer no-op, then add. Also compute a constrained oracle whose active options have at most 0.25 points of core recall loss relative to no-op, no new component split or neighboring bridge and less than 1% newly invaded area for each neighbor. The constraint uses truth only at oracle scoring. Report edited targets, active groups, strict IoU >= .90 transitions, FP/FN and core change, split/bridge and neighbor invasion.
