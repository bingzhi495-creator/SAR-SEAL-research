# Windows owner for the float-trained SSDD DEV187 pair

The owner reuses the byte-pinned P285 DEV187 source, P238 original resource guard, P206 Windows JobObject and P285 independent child readback. The existing P287 image-only stage is reused. Its published 187 logical/183 distinct JPEG attestation is pinned and the historical image-only root is checked again only after both new float E24 receipts pass. The original worker also checks the exact per-image input manifest. GPU export admission preserves the original 16 GiB host floor, 6 GiB free CUDA floor, 10 GiB original child RSS limit and 1,200-second stage wall limit. The separate CPU scorer hides CUDA and uses one compute thread with the original host/RSS/time limits.

## Source-only check

Use the original SSDD outer interpreter with `-I -B -X utf8 float_dev187_owner.py --check --stock-owner <pinned P285 owner> --worker <float_dev187.py> --protocol <float PROTOCOL.md> --code-root <ordinary release code>`. This verifies the actual bound source and the closed image staging summary without touching training state, images, labels, model archives, GPU or predictions.

Use an isolated config with exact fields `status=SSDD_FLOAT_COMMON_DEV187_WINDOWS_OWNER_CONFIG_V1`, `evaluation_protocol`, `work_root`, `dev_root`, `training_pair_ref`, `native_arm_ref`, `center_arm_ref`, `native_checkpoint_ref`, `center_checkpoint_ref`, `image_manifest_ref`, `float_gt_ref`, `integer_gt_ref` and `historical_ref`. Each file reference is `{path,bytes,sha256}` with an absolute forward-slash path. The work root is a fresh sibling under the original execution root with prefix `SSDD_WINDOWS_FLOAT_PRIMARY_DEV187_ACTUAL_PRIVATE_`. The DEV root is the original closed P287 image-only stage. The config can include both frozen label references because export stages use their metadata only. Actual labels open in the CPU score worker after both independent export receipts pass.

With the same source arguments, invoke `--run --stage EXPORT_NATIVE --config <config> --config-sha256 <sha>`. Retain the original tool session and natural terminal. Invoke `--accept` separately with the same stage and config plus `--wait <retained-external-wait.json> --wait-sha256 <sha>`. Repeat for `EXPORT_CENTER`, then `SCORE`. Each stage checks predecessors, keeps a separate original child and authority row, and cannot self-promote. Do not run a new stage until the preceding original tool closes and its independent acceptance succeeds.

The final stdout line of a successful run is the exact outer owner event. For its retained external wait JSON, copy the four join fields verbatim, change the status to the corresponding wait status, and append the actual `original_session_id` and unmodified final tool object as `exact_tool_wait`. The join fields are `stage`, `request_sha256`, `original_child_terminal_sha256` and `export_report_sha256` for the exports or `score_report_sha256` for CPU scoring. The wait status is `SSDD_FLOAT_COMMON_DEV187_EXPORT_ORIGINAL_TOOL_WAIT_V1` for the exports or `SSDD_FLOAT_COMMON_DEV187_SCORE_ORIGINAL_TOOL_WAIT_V1` for the score. Save the wait file outside the original stage directory. The accept action independently rereads the original Windows terminal, attachment, resource guard, stdout and report. It verifies exact output identities, both COCO score cells, fixed historical reference and gate arithmetic. The final safe aggregate is `INDEPENDENT_FLOAT_PRIMARY_SCORE_SAFE.json`.
