It does not modify U67/U70/U71 or any training/prediction source, bind a task,

The pure public API is:

```python
admit_population(input_refs, raw_inputs, *, proof_refs, prediction_refs,
                 endpoint, cpu_request, acceptance_source_ref)
```

- `proof_refs`: the authoritative four original Root-U75 accepted-proof refs in
  fixed range order. They are not owner receipts, postcheck snapshots, pending
  worker output or arbitrary files carrying `root_accepted=True`.
- `prediction_refs`: four actual original full U66_SHARD.json refs, one per
  proof. U74's smaller prediction_metadata projection cannot substitute for
  these complete files. Each ref must exactly equal its proof's prediction_ref.
- `input_refs`: exactly the path-sorted nine-ref union of those eight JSON files
  and the frozen U75 source. `raw_inputs` is a dict of exactly those actual paths
  to original `bytes`. Every byte count and SHA is checked before parsing.
  Missing/extra refs, conflicting paths, a copied proof, wrong file join or
  unlisted raw input is refused. Equal parsed JSON with different serialization
  does not satisfy the original file hash. No supplied verified-boolean or
  reencoding-based hash stands in for actual bytes.
- `endpoint`: the entire original accepted U58 FORMAL E50 endpoint dictionary,
  including both original checkpoints and source identity, not just37050.
- `cpu_request`: the original U70 seven-key request intended for future U71.
  Its shard_refs must equal the four prediction_refs in the same ordinal order.
- `acceptance_source_ref`: the actual frozen U75 code ref included in the nine
  inputs. The final content pin is fixed in this module. Whole admitted stdlib
  definitions are loaded without adding module aliases, and the original
  `validate_accepted_proof(proof,prediction)` is called for each pair. There is
  no production runtime/validator callback or unpinned-source mode.

## Trusted external observation and remaining connection

Pure JSON checks cannot establish that an OS process actually ran or that a
Root observation really occurred. Input selection and genuine original-tool,
owner/child birth/group, actual exits, sources and bytes remain trusted external
Root responsibilities. U75's strict schema/evidence joins reject owner/pending
substitutions but do not turn fabricated observation claims into reality.

Frozen U71 only byte-closes its external_shard_admission_refs. It does not call
this new module or understand its proof semantics. **Root must actually invoke
U76 with genuinely admitted original artifacts and bind its exact returned refs
and unchanged request before starting U71.** Merely implementing or staging U76
has not connected that live prelaunch gate. No actual four accepted E50 shards
or real invocation are supplied by this source task, and no CPU/AP/runtime
qualification has been granted.
