# SAMRefiner RGB400首张输入对应关系检查

本目录归档已实际完成并由Root闭合的首张RGB400输入比较。比较对象是历史缓存的FP32 RGB400与当前原始影像经固定geometry重建的RGB400。它检查输入是否相同，不评价SAMRefiner的分割效果。

## 已有证据

- 仅比较ordinal 0、image_id 4，原始图像尺寸317×420；比较张量均为CPU float32，形状`[1, 3, 400, 400]`。
- 数值不完全相等，原始连续FP32字节也不相等；最大绝对差`1.1771917343139648e-06`，RMSE `1.4736400118224847e-08`。
- `torch.allclose(atol=1e-7, rtol=0)`为false。该容差只作描述，未被用作方法质量门槛。
- 原工具、SSH、原始子进程与worker均返回0；对应执行组已确认退出。比较完成不以两路输入必须相等为成功条件。
- 没有访问GT、加载SAM模型、初始化CUDA、计算AP或增加训练更新；未进行全187张输入敏感性评价。

差异不能推出方法失败、AP下降、全187张都存在相同差异，或某种输入更好。不能据此声称当前原图与历史完整分辨率图像具有像素同一性。数值统计先将两路输入分别转为float64，再相减。

完整公开安全摘要见[结果JSON](../../results/U57_SAMREFINER_RGB400_CORRESPONDENCE_SAFE_RESULT_20261025.json)。后续输入诊断规则见[研究中途补充协议](../../U57_PROSPECTIVE_RGB400_INPUT_SENSITIVITY_POLICY_20261025.md)。

## 归档源码与依赖边界

`rgb400_check.py`和`test_import.py`按已闭合原件逐字节复制。模块开头的`Unexecuted`是准备阶段留下的历史描述；本次执行状态以本README和结果JSON为准，不表示这次比较未运行。结果JSON保存两份归档源码的SHA256。

worker在`main`内才导入科学库。它依赖受控SPEC、经哈希校验的自研读取与资源控制helper、单张输入及既有缓存；这些私有运行材料不随本目录发布。本目录不是脱离上述材料即可独立复现数值结果的完整数据包，不包含权重、原图、标注、第三方源码或私有运行路径。

现有测试只验证导入模块不会运行`main`或加载Torch/NumPy，不执行数值比较。在本目录内可运行：
