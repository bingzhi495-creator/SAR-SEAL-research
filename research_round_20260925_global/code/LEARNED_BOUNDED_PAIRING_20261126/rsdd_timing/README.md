# Reproduce the frozen Reserve74 operation timing

Run the two phases of `benchmark.py` with an observed, isolated invocation of the accepted CPython 3.10.13 runtime, NumPy 1.26.4, SciPy 1.15.3 and pycocotools 2.0.11. Set `CUDA_VISIBLE_DEVICES=-1` and set `OMP_NUM_THREADS`, `MKL_NUM_THREADS` and `OPENBLAS_NUM_THREADS` to `1`. Use the original observer's `prepare-edits` phase for collection and `verify-edits` for the benchmark. The observer must record natural exit 0 and a matched output footer. The CLI help lists the explicit archive and result inputs for each phase.

For `collect`, supply the frozen source head, the closed reserve archive and the earlier [bounded pairing renderer](../rsdd/render.py). It binds the actual historical reserve render receipt and terminal by digest. The authority holder keeps the resulting private candidate cache and original run payloads. For `benchmark`, supply the closed collection's aggregate result, observed terminal and the independently verified hashes of both. This phase reconstructs every earlier F/L/I mask before timing. The data and point head retain their original access procedure.

The selection clock starts after preprocessing and candidate cache load. F consumes original pair rows and k, ranks the pair differences and selects k rows. I consumes the same cached inputs, runs both stable endpoint sorts and breaks ties by the same original pair-row ordinal. Neither times the original Hungarian distance assignment. L uses the inherited cap and times its own geometric computations, feasibility test and exact bounded matching. RLE application is timed separately on the same inputs through one shared implementation. These timings apply to the tested CPU implementation and cached local stage.

The synthetic test takes the released sibling solver by default. If testing an external staging directory, set `SAR_BOUNDED_MATCH_SOLVER` to the exact matching file. The two released JSON summaries contain only aggregate results and digests. The collection and timing terminal digests are `032a18f60fbcbdfdabb0823ebb511a1520468205a550c361016efbb933005b43` and `fbe5141b3d04c07f2b062243afdd04ae24d9c3fa6a69e80cd445bc932652f9fc`.
