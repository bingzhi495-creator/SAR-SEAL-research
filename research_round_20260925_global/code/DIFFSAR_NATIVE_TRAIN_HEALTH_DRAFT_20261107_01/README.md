# DiffSAR native finite training-health candidate

2026-11-07. Draft completed locally; **not bound, imported into a scientific runtime, or executed**. Only standard-library tests have run. Root owns the later one-attempt lease, source/input freeze, resource admission, original tool and process identities, and external closure. This candidate cannot authorize itself.

The question is whether the zero mask-branch gradients seen on the first random-initialization FIT case persist when the original model takes actual optimizer updates on different real FIT cases. It is not another repetition of that one case and is not an efficacy/AP experiment. The earlier failed probes retain their original failure and do not become successful if this pilot completes.

The worker consumes 32 canonical logical rows (dataset indices 0 through 31) from the complete pinned FIT population, with one optimizer update for each row. It never chooses images according to gradient values, skips an empty-after-augmentation case, changes augmentation, or replays a case. The full inputs are 741 logical images and 1661 canonical annotation instances, represented by 730 unique JPEG byte objects. Repeated bytes do not deduplicate the training population. `canonical_input_plan` validates this relationship; native COCO records are joined by original image and annotation identities and then reordered to the fixed manifest order. The original COCO JSON is not rewritten. Native `load_coco_json` uses a nonempty dataset metadata name so that the single original category maps to contiguous class 0. Native polygons/BitMasks and original mapper transformations are retained.

The author R101/SCJE model, 500 proposals, six heads, all 24 original weighted losses, constant-prior initialization, and float64 diffusion buffers are unchanged. No weights are loaded. The public YAML's MODEL.WEIGHTS is null and the paper's actual initialization provenance remains unresolved: this is explicitly the public-code construction initialization, not a certified reproduction of the paper's initialization.

The native `train_net.Trainer.build_model`, `build_optimizer`, and inherited `build_lr_scheduler` are called. The original one-parameter-per-group AdamW, backbone multiplier 1, weight decay 1e-4, global norm clipping 1 in the native optimizer step, base LR 3.5e-5, MAX_ITER 18560, milestones 14848/17632, warmup factor 1 and warmup iterations 10 remain intact. The scheduler's complete schedule is not shortened to 32. The bounded outer loop stops after 32 actual updates; the scheduler steps after each optimizer step, as in the original hook. The original batch size is already one. Worker count zero, fixed canonical InferenceSampler order and seed 40244023 are disclosed finite-health adaptations instead of the author's shuffled multi-worker sampler. The native data loader, author mapper and aspect-ratio grouping setting are used. No Trainer instance is constructed, avoiding its evaluation/checkpoint hooks.

The report captures actual native optimizer defaults (including betas, eps, foreach/fused and related flags), together with the effective parameter-group weight-decay values. Defaults alone do not override the explicitly configured per-group decay.

Every step records the actual logical input identity, instance count after unchanged augmentation, mapped shape, original losses, learning rates, finite-present-gradient result, IAMR/six controller gradient summaries and shared-output total gradient. The shared output is retained with a forward hook that returns None and never substitutes its value or adds another backward. Its derivative is classified as NONE, FINITE_ALL_ZERO, FINITE_NONZERO or NONFINITE; present nonfinite derivatives fail health, while zero or absent derivatives are valid recorded observations. All present parameter gradients must be finite, but no scope is required to be nonzero. Normal completion means 32 distinct canonical logical samples, finite original losses/present gradients, actual optimizer step returns, and proper resource/source cleanup—not successful mask learning or method validity.

At requested updates 1, 8 and 32, the worker records the original post-backward gradients and parameter copies before native clipping/step, then actual selected IAMR/controller changes after the native update. The first record is also the update-count-0 observation before the first update; there is no extra forward/backward. A tensorwise decay-only reference is made without running another optimizer or modifying parameters. Actual changes and residuals above a conservative FP32 roundoff bound are reported together with gradient presence/nonzero elements. Parameter motion alone is not fresh data-gradient evidence: AdamW momentum, weight decay and rounding matter. No model/optimizer checkpoint or continuation weight is saved, and these updates carry no main-run or formal-baseline training credit.

The worker uses CPU0/1, two threads, CUDA0 FP32 without TF32/AMP, an 8GiB allocator cap, 16GiB worker/group RSS bound, 16GiB minimum free RAM, 48GiB startup free RAM and 1800-second deadline. Root's existing external supervisor remains responsible for group RSS, parent/library child identities, whole-group deadline and cleanup. The worker records exact selected imported module refs, verifies the config/adapter/binary pins and all 730 unique JPEG refs before and after execution, and demands fresh outputs. Its selected-source guarantee does not cover every transitive runtime file or a wholly isolated environment. An OOM or resource stop is preserved as such, with no automatic retry or reduction of the 32-update task.
