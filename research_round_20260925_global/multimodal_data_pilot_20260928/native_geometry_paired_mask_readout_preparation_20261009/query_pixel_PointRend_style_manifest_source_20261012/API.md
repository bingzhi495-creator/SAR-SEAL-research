## Contract and ordering

The original four training RAWs, restoration RAW and head-only fixture owned
CPU RAW all pass before any SHA, SOURCE load or manifest write. The CPU branch
also gates this C technical GPU RAW first. Receipt paths must be absolute
`PARENT_RECEIPT.json` with parent equal to explicit phase; if RAW has phase it
must be an exactly matching string. Nonempty exact-dict process identity,
integer return/held-exit zero, actual held/reaped/birth absence, no errors and
whole-card observed resource scope remain mandatory. Admission digest must be
64 lowercase hexadecimal characters. No RAW is rewritten or enriched.

`ancestor_admissions` has exact rows `{receipt:REF3,phase:str,admission:REF3}`.
The old qualified RAW references and original input closure are preserved.
New explicit references to actual historical admissions and their verified
inputs are added to this C closure; they need not have been named as new roles
in an old template. Actual phase/driver/entry/CLI/input hashes must agree with
the RAW. Missing qualified references, files or inconsistent identities reject
authoring; the generator never fabricates an old admission.

GPU outputs a fresh technical SPEC (existing C schema) and owned GPU admission.
CPU outputs only a fresh owned CPU admission, preserving the GPU SPEC. It binds
the complete C source closure, own GPU admission/RAW, REPORT/START/aggregate,
checkpoint/proof/order/trace/epochs and all four audits. It does not emit CPU Q.
All fixed SPEC/admission/acceptance/output/runtime paths must remain fresh.

`stage_kind=technical`, `arms=[C]`; owned admission status remains
`ROOT_OWNED_SINGLE_ATTEMPT_LOCAL_DIAGNOSTIC_PHASE`. GPU phase is
`query_pixel_PointRend_style_C_technical_20261012_01`, with distinct CPU phase
`query_pixel_PointRend_style_C_technical_CPU_20261012_01`. Future CPU Q must come
from the pinned C reader: schema
`ROOT-query-pixel-PointRend-style-native-integration-CPU-qualification-v1`, status
`ROOT_QUERY_PIXEL_POINTREND_STYLE_NATIVE_INTEGRATION_CPU_QUALIFIED`, with
`stage_kind=technical` and `formal_initializer_qualified=False`. This document
