# N22：平均 IoU 余量与阈值通过数分歧的定点实例

这是已完成并经 Root 接收的 N22 `ANALYSIS.json` 与 `CPU_REPORT.json` 的描述性计数检查；未读取图像、GT 张量、权重或 GPU packet，未新增实验。原人口仍为固定 32 FIT 图、全部 3200 natural queries 中原 matcher 的 53 个真实 GT 配对；未配 query 不构造背景 GT，分母与主指标不变。本表不是独立验证，也不选择新研究方向。

记 N 为 native，R 为同一次 full-C GPU 动作限制在固定 Omega 的路由结果，P 为固定 PR 有益动作的 at-most-K oracle，G 为候选 C 内 GT 错误翻转的同预算 oracle。routegap=P−R，headgap=G−P。四者均为固定配对 IoU，不能解释为 AP 或 AP 上界；R 也不等同于历史另跑 S-only forward 的逐位复现。

选择规则在查看实例前确定，并保持不变：A 组要求 headgap>routegap，且 R<0.95≤P、P→G 不再新增通过 0.95；B 组反向要求 routegap>headgap，且 P<0.95≤G、R→P 未新增通过 0.95。各组按原 `pair_id` 字典序取前 3 条。A 组符合条件 5 条、展示 3 条；B 组符合条件 1 条、展示 1 条，合计 4 行，不为补足表格改变规则。

IoU 按百分数展示；两 gap 的单位是 IoU 百分点，保留 4 位小数仅为排版，分组和阈值判定使用原精确有理数。区域列记为 `C点数 · native FN/FP · PR有益FN/FP/有害TP/TN`；区域 native FN/FP 来自完整原图，包含 C 外错误；PR 计数仅来自 C。各区不重复分配 K，不分别求 oracle 后相加。

A 组三例的 P 均已超过 0.95，后续更大的 headgap 无法再增加最高固定阈值 0.95 的通过数；P 已超过全部十个固定阈值，后续也不会增加其他阈值通过数。B 组的 P=94.9275%，更大的 routegap 仍使它停在 95% 以下；随后较小的 headgap 才跨过该阈值。这直接展示了阈值位置及最高阈值封顶如何产生与连续 IoU 余量不同的排序，不能把通过数较多自动等同于 IoU 余量较大。

全体 53 配对的原结果为平均 routegap 2.2956 点、headgap 2.5011 点，十阈值新增通过总数分别 22 与 20。本表提供算术层面的反例，**不声称这 4 行解释全局全部差额，也不证明冲突只由少量实例决定。**

所示实例没有建立一致的机制归因。A 组三例 Omega 外的 PR 有害 TP 数为 16、6、22，B 例则为 0，且存在 9 个有害 TN；四例的 native FP 与 PR 可修 FP 均为纯背景，不能据此外推其他船舶混淆的全体占比。实例按上述数值冲突条件筛出，缺少独立机制检验。不能由此确认 query 条件是主瓶颈、普遍带外能力不足，或某一新结构有效。实际 PR 门控与训练域来源仍需另行核清，再决定是否预锁同结构、相同 full-C 训练域和采样的强对照，随后检验结构贡献；本表没有预锁新训练。GT 仅用于离线诊断，不用于选择 C、S 或模型输入。
