## Question and fixed cohort

The competing explanation is that either ranker relies mainly on the original mask, candidate grid and scores, so an image-only displacement need not move the final signed edits. This is a diagnostic on the same already scored 74-chip, 13-parent Instance-RSDD cohort. The previous equal-count Phoenix comparison gave a higher AP for Phoenix and inconclusive fixed-match continuous IoU. It did not determine which rank is more sensitive to image alignment. ## Intervention and verification

Shift the native RGB input to each ranker alone by one native column in both directions. Positive right shift means new input column x contains old column max(x−1,0); negative left shift means new input column x contains old column min(x+1,511). The new endpoint coordinates do not move. Use border replication, no wrap, no rescaling, no image rotations or vertical shift. Keep original detector, candidate ROI, input mask, fixed logit plane and all non-image features. Regenerate the existing occupancy image feature input only and verify the original frozen endpoints are unchanged. On every candidate, the unshifted occupancy reconstruction must reproduce the accepted archived equal-count mask for each seed. Phoenix provides same-original-grid probability for every original endpoint, from separate label-free shifted runs. Require complete actual closure and exact source, request, signed counts and edited-mask parity. Static attraction uses the original mask and no image in this experiment and is an exactly zero structural response control.

Assemble signed edits by decreasing add probability and increasing remove probability at the same archived k of both signs. Validate edited position sets and signed counts using the independent native-pixel reconstruction. Zero/invalid count candidates remain exactly native. Retain unchanged file IDs and originals. Both image shifts and all matched edit arms must close before labels are opened. Reproduce unchanged original metrics on all views used.
