# Instance-RSDD 74-chip classical attraction control

## Question and fixed scope

At the same signed boundary edit budget, does HRSID-trained occupancy order beat a classical spatial attraction order on the previously evaluated Instance-RSDD parent-reserve cohort? Earlier historical author test results used the same frozen RF-DETR and two occupancy seeds, and reported a GF-3 advantage over dynamic attraction. The separately prespecified 74-chip parent-reserve cohort has already supported same-geometry and PointRend comparisons. This control asks whether the advantage on that cohort survives the image-free, strong spatial alternative. Keep the author-test result and its original stopping rule as historical context. The current work does not add model evaluations to the 740-chip author test. ## Interventions and verification

Use the [published spatial-attraction implementation](code/FIT109_CLASSICAL_ATTRACTION_20261121/spatial_attraction.py), adapted from Atkinson to the existing signed native endpoint set. It ranks by a radius-five exponential neighbor occupancy sum, with the previously used scale five and deterministic original endpoint tie order. Dynamic selects highest attraction additions and lowest attraction deletions, updating neighborhood occupancy after each positive-gain swap and stopping at the existing cap. That exact realized count k defines all five edited arms. Static selects initial attraction-ranked positions at k. Each frozen occupancy head picks its highest occupancy additions and lowest occupancy deletions at k with the original tie convention. Keep raw stock as a separate reference. All arms retain the original mask when k=0, outside the area gate or without usable endpoint support. No alternative support, count proposal, score adjustment, target tuning, or fitted classical parameters are introduced. [Atkinson original](https://doi.org/10.14358/PERS.71.7.839) · [Source-supported same-count classical control](HRSID_DEV705_CLASSICAL_ATTRACTION_ACTUAL_20261122.md)

Use the qualified 74-chip stock capture, verified occupancy lineage and matched PointRend roster reader. PointRend predictions are not resubstituted in any arm. Recover the complete original roster, original logits/features and seeds. Recheck the archived seed-5217 natural policy and exact signs, count and mask area for every new edit. Independently re-execute all image-side choices with the same pinned code, bounded workers and distinct output. Require equivalent complete edit bytes, zero optimizer/detector updates, successful observed exit and valid hash-linked output for both stages before label scoring. Scoring verifies every edit and untouched candidate, restores the author COCO test semantics for the 74 admitted image IDs from annotation_coco/train.json, and checks prior exact raw metrics.
