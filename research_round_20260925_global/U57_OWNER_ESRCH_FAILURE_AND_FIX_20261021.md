## 根因与最小修改

监督器需要枚举进程并读取进程状态。进程在枚举和实际读取之间退出时，读取可能报告对应进程已不存在。原实现只将 `FileNotFoundError` 作为该单个进程已经消失处理；本次实际出现的是 `ProcessLookupError`。Python 官方文档将后者对应于 ESRCH，前者对应于 ENOENT，两者是不同异常类型。[Python 3.12 内置异常文档](https://docs.python.org/3.12/library/exceptions.html#ProcessLookupError)

候选修复只改变 `proc_identity` 中的一处异常分支：

```python
except (FileNotFoundError, ProcessLookupError):
    return None
```

该分支只表示被读取的单个进程已消失。没有扩大为捕获全部 `OSError`，权限拒绝、一般 I/O 错误、其他异常和无效状态格式仍向上传播；PID 出生标识、进程组、资源上限与成功接纳条件均不改变。模型、优化器、数据、训练配方、更新目标和评估规则均不改变。严格的结束后独立进程核验器也未因本修复放宽。
